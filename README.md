## Что умеет
- Отвечает клиенту через ИИ (Gemini API, бесплатный тариф) как консультант — работает и в Telegram, и в Instagram (Instagram подключается через ManyChat)
- По ходу разговора ненавязчиво узнаёт имя, телефон и что интересует клиента
- Как только новое поле профиля заполнено — шлёт менеджеру карточку клиента в Telegram (с пометкой канала: Telegram/Instagram)
- По триггер-словам ("менеджер", "человек", "оператор") или команде `/takeover` замолкает и передаёт диалог тебе — вместе с уже собранным профилем
- `/release <user_id>` — вернуть диалог ИИ
- В Telegram: принимает запрос на оплату, присылает ссылку на Kaspi, ждёт скриншот чека, пересылает его тебе. Для Instagram эта часть пока не подключена (см. "Известные ограничения")
- `/confirm_payment <user_id>` — подтвердить оплату вручную

## Запуск
1. `python -m venv venv` (Windows: `venv\Scripts\activate`)
2. `pip install -r requirements.txt`
3. Заполни `.env`:
   - `BOT_TOKEN` — токен от @BotFather
   - `GEMINI_API_KEY` — ключ с aistudio.google.com/apikey (бесплатно, без карты)
   - `MANAGER_CHAT_ID` — узнать свой id можно у бота @userinfobot
   - `KASPI_LINK` — ссылка на оплату Kaspi.kz, которую увидит клиент
   - `MANYCHAT_WEBHOOK_TOKEN` — произвольная секретная строка, защищает вебхук от чужих запросов из интернета
   - `WEBHOOK_PORT` — порт для вебхука ManyChat (по умолчанию 8000)
4. `python main.py`

### Про DeepSeek/OpenRouter
Пробовали DeepSeek через OpenRouter вместо Gemini — по факту сейчас (сентябрь 2026) у DeepSeek там нет бесплатного тарифа, а бесплатные модели-заменители (`openrouter/free` и т.п.) на практике оказались нестабильны: путают кириллицу и упираются в лимит запросов после нескольких сообщений в день. Поэтому в `ai.py` сейчас снова Gemini — он реально бесплатный и уже проверен в бою. В `.env` оставлены `OPENROUTER_API_KEY`/`OPENROUTER_MODEL` про запас: если решишь пополнить баланс OpenRouter (пара долларов, openrouter.ai/credits) и попробовать платный `deepseek/deepseek-chat-v3.1` — это будет отдельная небольшая правка `ai.py`, дай знать.

## Как это работает по шагам
1. Клиент пишет боту (в Telegram напрямую, или в Instagram → ManyChat → наш вебхук) → сообщение уходит в `ai.py` → ИИ отвечает как консультант и попутно спрашивает имя/интерес
2. После каждого ответа бот отдельным лёгким запросом прогоняет всю переписку через `extract_profile` и вытаскивает имя и интерес. Телефон обрабатывается отдельно и без ИИ — простым поиском по цифрам в сообщении, поэтому попадает менеджеру ровно в том виде, как написал клиент
3. Как только появляется новое поле — карточка клиента улетает в `MANAGER_CHAT_ID`
4. История и профиль хранятся в SQLite (`storage.py`, файл `bot.db`) — переживают перезапуск бота
5. Если клиент пишет "оплата" (в Telegram) — бот присылает ссылку Kaspi и ждёт чек
6. Клиент шлёт скриншот чека → он летит тебе в `MANAGER_CHAT_ID` с кнопкой-командой для подтверждения
7. Если клиент просит менеджера — бот замолкает для него; для Telegram-клиента ты переписываешься вручную через самого бота, для Instagram-клиента — напрямую в Live Chat в ManyChat

## Instagram через ManyChat — как подключить
Наш бот поднимает HTTP-эндпоинт `POST /manychat/webhook` (по умолчанию порт 8000), который ManyChat дёргает через блок **External Request** при каждом сообщении клиента и получает готовый ответ ИИ.

1. **Публичный адрес.** ManyChat стучится к нам из интернета, а не с локальной машины, поэтому нужен публичный HTTPS-адрес, который смотрит на `localhost:8000`. Проще всего на время пробного периода — туннель, например `ngrok http 8000` (после `ngrok config add-authtoken <токен из аккаунта ngrok>`). Каждый перезапуск ngrok меняет адрес — придётся обновлять URL в ManyChat, пока не переедете на постоянный хостинг/домен.
2. **Блок в ManyChat:** Automation → добавь шаг **External Request**:
   - Method: `POST`
   - URL: `https://<ваш-ngrok-адрес>/manychat/webhook`
   - Headers: `X-Webhook-Token: <значение MANYCHAT_WEBHOOK_TOKEN из .env>`
   - Body (JSON):
     ```json
     {"subscriber_id": "{{subscriber_id}}", "text": "{{last_input_text}}"}
     ```
   - Response: оставь как "Dynamic Block" / v2 — наш вебхук уже возвращает готовый формат, ManyChat сам отправит текст клиенту
3. Повесь этот блок на триггер "любое новое сообщение" в основном flow, чтобы каждое сообщение клиента уходило к нам и ответ ИИ возвращался тем же шагом.

Instagram-клиенты в нашей базе хранятся с отрицательным `user_id` (техническая деталь: чтобы гарантированно не пересекаться с Telegram id) — в карточке клиента и командах `/takeover`, `/release`, `/history`, `/confirm_payment` просто используй id как он показан, включая минус.

## Известные ограничения Instagram-канала (пока)
- **Оплата.** Флоу "оплата → ссылка Kaspi → ждём чек" пока реализован только для Telegram. Для Instagram проще всего сделать оплату отдельным блоком прямо в ManyChat (кнопка/сообщение со ссылкой на Kaspi по ключевому слову), не заводя её через ИИ-вебхук.
- **Проактивные сообщения** в Instagram работают только при заданном `MANYCHAT_API_KEY`.
- Ручной режим (`/takeover`) для Instagram означает "ИИ больше не отвечает" — сам ответ клиенту менеджер пишет прямо в Live Chat ManyChat, не через нашего бота.
